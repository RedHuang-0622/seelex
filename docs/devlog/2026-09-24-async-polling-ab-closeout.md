## 2. 竞态：从"潜在"升级到"实测存在"

| 命题 | 修之前能证明吗 | 现在的证据 |
|---|---|---|
| 旧形状是数据竞态 | 不能——`-race -count=3` 没抓到，只能写"潜在、窗口窄" | 能：`async_exec_raceproof_test.go`（tag `raceproof`）复刻旧口径，`-count=5 -race` 实测报 `DATA RACE`（写=收尾改 `state/exit`，读=锁外整结构体拷贝） |
| 修法正确 | — | `begin` 与 `snapshot` 同口径按值返回副本；`TestAsyncRegistryBeginHandsOutACopy` 钉语义（回执渲染派发那一刻的状态，命令同瞬间结束也不回头改写）；修后 `-race` 全绿 |

窗口为什么窄：只有"回执正在拷贝"撞上"命令恰好这一瞬结束"才会踩到。**这类竞态不能用
"日常 -race 没报"来判它不存在**——反证用例的职责就是把这句话变成可跑的实验。
该用例**预期报红**，已在 §9 验证命令里写明，免得后来人当坏测试修掉。

## 3. 泄漏：目录比进程活得久

- 修复前现场：临时目录 **44 个** `seelex-async-*`。驱逐只删单条记录的文件，没有任何路径
  会删进程自己的目录。
- 修法（三条）：`Router.CloseAsync` + `asyncRegistry.close` 登记进 `Runtime.Shutdown`
  逆序链；close **当场试删**，删不动就记下意图，由**最后一条 `finish` 补删**；关停后
  `begin` 报错，不再新建无人回收的目录。为什么用"删得掉吗"而不是"表里还有没有 running"
  作判据：只登记、没启动执行体的在途记录根本没有句柄，按 running 判会把目录永久留住——
  删除结果自己就是最准的答复。
- 实测闭合：隔离跑一次 B 臂回合，前后计数 **49 → 49**；全量矩阵 9 个 B 回合各 +1（运行期）、
  收尾后无净增。
- 顺手收掉测试自己的残留：一轮 `go test ./seelebridge/tools` 曾留下 5 个目录
  （`owner-only-marker` / `incremental-marker` / `ack-payload-marker` 这些 fixture 写在
  `a1.log` 里，正是它们让矩阵期间那 +5 一度被误记到 A/B 头上）。脚手架挂 `t.Cleanup` +
  派发型用例等执行体收尾（`waitAsyncTerminalForTest`，终态在 `file.Close()` 之后才合成），
  连续两轮单测 **59 → 59 → 59**；补删那条分支由 `TestAsyncRegistryCloseSweepsLateFinish` 钉住。

## 4. §8.3 五指标 A/B：硬判据过、成本判据不过

两臂只差 `limits.async_exec.enabled`（同一二进制内翻开关，比两次构建对照更严格；
§8.4 原文要求 worktree 基线的前提——未提交的前端改动——已随 `973bb80` 消失，该偏离已在
报告 §2 交代）。3 任务 × 每臂 3 次 × A/B 交替，真 API + 录制代理。

| # | 判据 | 结果 | 判定 |
|---|---|---|---|
| 1 | 墙钟 B ≤ A（硬） | 合计 68.43s → 49.53s；**逐任务**：T3 22.86→4.88s（−78.6%）、T1 −3.2%、T2 −0.9% | 成立 |
| 2 | 缓存比率 ≥ A−2pp | 0.948 → 0.956；B 臂轮内 0.94→0.96 稳定爬升 | 成立 |
| 3 | 总 prompt ≤ A×1.10 | **+158%**（未命中口径只 +807 token/任务） | **不成立** |
| 4 | 结果真进上下文 | T1/T2 标记进入 `async_output` 之后的请求；T3 完成取回 | 成立 |
| 5 | 进程归零 / 目录有界 | 18/18 leftover=0；目录运行期 +1、收尾回收 | 成立 |

**结论按事先写死的判据给，不事后放宽**：不触发回滚（判据 1、5 是硬条件），但也不能说
"划算"。墙钟收益全部集中在"不必等结果"的 T3 形状；只要回合最终必须报出命令输出，下限就
是命令本身的 20 秒，重叠掉的只有几次文件读写的 LLM 往返。成本则长在**轮次数量**上——
每多一轮就重发一次 ~4700 token 的信封。所以切片保持默认关，打开要按
"命令时长 × 有没有可并行的活"判断。

方法学上补了一条会反复咬人的口径（报告 §4 第 4 点、工作包 §0）：**两臂工具 schema 不同 ⇒
缓存前缀不相交 ⇒ 每套 schema 的首个请求必付一次冷 miss**。校准轮里 B 臂 r1 一度测出 0.09
（对照 A 臂 0.93），拿单点比率就会得出"轮询破缓存"的反向结论；必须看轮内序列与未命中字节。
