## 1. 事实先行：Qoder 的"纸"到底怎么圆的

复刻页/设计语言里"纸是方的、只有 1px 发丝线"的说法不够用——要把圆角加上去，得先知道
Qoder 实机圆多少、缩不缩进。用既有量法（`tools/measure-skin.py` 同族）逐像素扫
`refs/qoder-light-clean.png`（1920×1080）：

| 位置 | 剖面 | 结论 |
|---|---|---|
| 纸·顶左 | (323,56) → (316,63) 收进 7px | 圆角 **≈7px** |
| 纸·顶右 | 1907 → 1913（+6px） | 圆角 **≈6–7px** |
| 纸·底（y=1070） | 左 319 / 右 1910（＝比中段各进 3px） | 下角同样收圆 |
| 纸·左边（y=63..1039） | 恒为 x=316 | **四边不缩进**：纸与壳齐平，只在角弧里露壳 |

**判据**：圆角是"圆弧里露出壳"，不是"缩进留白槽"。所以落地不需要 margin、不需要描边，
只需要"给纸一个 8px 圆角 + 让壳在纸背后透出来"。本产品的中栏就是那张纸
（`.workspace` 是 `.app-shell` 的子节点，背后就是壳的渐变）。

同轮发现一处**换代的残留**：`.conversation-tabs` 的底色还是 `var(--bg)`（#f7f6f2）——
那是渐变落地前的壳色，压在白纸上就是第三种颜色，而且会把纸的上面两个圆角抹平。

## 2. 改法

### 2.1 中栏 = 一块带圆角的纸（`styles.css` 第 27 节 n）

```css
.workspace { border-radius: var(--r-md); }        /* 8px：与 Qoder 实测同档 */
.conversation-tabs { background: transparent; }   /* 让页签条成为纸的一部分 */
```

- 子节点（子页页签条 / 终端面板 / composer）由 `.workspace` **既有**的 `overflow: hidden`
  一起裁圆，不需要各自加圆角；
- 半径取 `--r-md`(8px) 而不是 `--r-xl`：实机就是 7–8px，且撞上"一屏只有一处 ≥14px"
  那条（那处是 composer）；
- 页签条的横向滚动暗示走 `box-shadow`，不靠 `background`，所以清底色不误伤它。

### 2.2 页签家族补齐最后三处（`styles.css` 第 27 节 o）

第 27 节 j)（§2.5 的同一次换代）只覆盖了对话区与右栏页签，剩下三处仍是"**圆角 + 单边色条**"的老写法
（就是用户点名的那条丑）：

| 选择器 | 原写法 | 现在 |
|---|---|---|
| `.excel-sheet.is-active`（工作表页签） | `3px 3px 0 0` + `inset 0 -2px 0 status-running` + `var(--shadow-sm)` | `var(--r-md)` + 同色系薄底，下条与投影删 |
| `.terminal-tab.is-active`（终端页签） | `var(--r-sm)` + `inset 0 -1px 0 var(--accent)` | 同色系薄底，下条删 |
| `.schedule-pill.is-next`（发言调度） | `999px` + `inset 0 -2px 0 accent55` | 同色系薄底，下条删 |

旧声明**从源头删掉**，不留"被后写覆盖"的残留——P0-2 的 1/2/3 当初就是这么漏掉的（27 节 j
只重写了 `box-shadow`，`::after` / `::before` / `border-color` 三条没人管）。选中态现在
只在第 27 节 j)、o) 两处定义。

收尾自检时抓到一处**残留**：`.excel-sheet` 的**源声明**里还留着硬编码的
`border-radius: 3px 3px 0 0`（27 节 o 只是把它覆盖成 token，源里那条没人删——正是上面这条
口径要防的形状）。已把源声明也改成 `var(--r-md)`，现在全文件硬编码的"上圆下直"
（`Npx Npx 0 0` 字面量）**0 处**；这条由 `theme.test.mjs` 的
"选中态高亮只由皮肤派生"用例钉住（它同时钉了 `inset 0 -Npx 0` 与"圆角 × 纯黑同块"两条黑名单）。

### 2.3 上下文压缩块归位（`index.html` + `app.js`）

用户口径「上下文压缩内容需要放到状态的概要下面」——即回到 `#status-panel` 折叠区**里面**、
紧随概要。这与 2026-09-24 早先"挪到折叠区外面"的处置相反（`…-compaction-frontier-singleton-and-frame-popup.md`
§2.4 当时的理由是：折叠起来时进度条与记录整块消失，"按下回车到底动没动"就没人回答了）。

所以这次**两条一起落**，否则任一条单独执行都会复现旧问题：

1. `#context-compactions` 移进 `#status-panel`，排在 `#project-overview`（概要）之后；
2. 折叠区默认收起，可见性改由视图侧兜住：`repaintCompactions` 见到本轮门禁进度
   （`compactionProgress`）就调用新的 `revealStatusPanel()` 把折叠区打开（**只开不收**）；
   历次记录不触发打开——那是用户展开 状态 才读的静态事实，自动弹开会跟用户手动收起打架。

两条口径都钉了测试（`gui/frontend/dist/status-panel.test.mjs`，2 条）。

### 2.4 员工库 / 团队库 / 员工栏 / 团队配置：一块只管一份事实

先把三份事实摆清楚（此前只在代码注释里零散写着）：

| 块 | 唯一职责 | 事实域 |
|---|---|---|
| **员工库** | 员工是谁 + **档案（提示词/权限/类型）的唯一编辑入口** | 全局母本 `<root>/team/employees.json` |
| **团队库（团队配置面板）** | 一支团队**有谁、什么顺序** | 全局母本 `<root>/team/library.json` |
| **员工栏** | 本会话**在编名单 + 发言顺序** | 会话副本 `session/team/roles.json` + `lifecycle.order_policy/order_roles` |
| 发言调度 | 运行态只读 | `TeamView.schedule` |

**耦合点（已删）**：员工栏行内的「编辑」打开的是**会话作用域**的入职/修改面板——同一个人
在员工库与员工栏各有一套"改提示词 / 权限 / 类型"的按钮，写两份事实、必然漂移（视图侧
因此得靠 `teamGlobalDrift` + 「入库」+ 漂移提示兜着）。现在：

- 员工栏行内动作只留本会话的两件：✕ **摘除**（出工作顺序、留角色）与**删除**（连会话注册表
  一起删）；档案只**回显**，chip 的 `title` 写明"本会话在编副本"；
- 改档案回员工库改，再「入职」一次即覆盖副本（同 `role_name` 幂等覆盖）——这是既有语义，
  没有新增后端能力；
- `app.js` 里接 `data-team-edit` 的分支随之删除（没有读者的契约不留）；
- 三块栏头的 `title` 各自写明事实域。**不**在栏头摆可见的域标签：上一轮已把"栏头摆注解文字"
  这条口径钉掉（`agent-team-view.test.mjs` 的 "head carries no annotation text"），域只在 hover 里说。

保留的判断：`.excel-grid .work-row.is-*` 的状态色左轨、`.team-table` 的表格线——那是**语义**
与**数据**，不是装饰；没动。

### 2.5 按钮高亮 / 页签家族换代：从"书签拟物"到"静止胶囊"

（本提交的另一半，先记在这里——§2.2 说的"27 节 j)"就是这一节。）

用户点名的是右栏三个子页（状态 / 工作台 / 资源管理器）的**按钮高亮**。改之前它们是
"纸质笔记本书签"拟物：`.right-tab.is-active` 用 `--accent` 实心渐变底 + 1px 深色描边 +
`::after` 的 `clip-path` 尖角 + `::before` 的纸面高光 + `0 3px 8px rgba(0,0,0,.30)` 投影。
在 Qoder 皮肤下 `--accent` 近乎黑（#1f2328），所以这一套读出来就是"**黑块 + 黑外框**"；
页签家族另外三处（工作表页签、终端页签、发言调度胶囊）又是"圆角 + 单边黑下条"，正是用户
同一轮说的"**圆角配上一个黑色的下外框**"。

**新口径**：选中态 = 同色系薄底 + 同色系重字，不描边、不加下条、不投影、不做位移。
两个派生 token 只声明**一次**（浅色基座，深色靠 `--accent` / `--surface` 的桥接自动跟随）：

```css
--hl-fill: color-mix(in srgb, var(--accent) 14%, var(--surface));  /* 当前皮肤色系的一层薄色 */
--hl-ink: var(--accent-strong);                                    /* 同色系重色 */
```

五套皮肤不必各写一份——否则"皮肤 × 深浅"就是十份事实，换皮肤必然漏一处。

落点：

| 文件位置 | 改法 |
|---|---|
| `styles.css` `:root` | 新增 `--hl-fill` / `--hl-ink`（派生 token，随皮肤与深浅自动变） |
| 第 19 节 `.right-tabs` / `.right-tab` | 下线书签拟物：`border: 0`、`::after` 尖角与 `::before` 高光整块删掉、去掉 `transform` 位移；栏脊对齐从 `flex-end` 改 `center`（没有"立起来的标签"了） |
| 第 5b 节 `.conversation-tab` | 同一族：原来是"上圆角 + 2px 黑下条"（`border-radius: r-md r-md 0 0` + `border-bottom: 0` + `inset` 条），改成 `border: 0` + 全圆角胶囊 |
| 轨迹一节 `.trajectory-row` | 同类判定：左侧 3px 状态色轨与圆角**互斥**（圆弧会把色轨上下端各切一刀，看着像"[ 括弧"）→ 行与行头都取方角，让色轨通到顶底 |
| 第 27 节 j) / o) | 选中态集中在这两处定义：j) 覆盖对话区 / 右栏子页，o) 覆盖工作表页签 / 终端页签 / 发言调度胶囊 |

"高亮是不是黑的"这件事不能靠读代码判断——`--accent` 是皮肤给的。所以判据取**真渲染的
绘制值**（未 hover 的新建元素，排除 `:hover` 干扰）：`background` 是薄底、`color` 是同色系
重字、`boxShadow: none`、`border-width: 0`；五皮肤 × 深浅的色值与对比度见 §3。
