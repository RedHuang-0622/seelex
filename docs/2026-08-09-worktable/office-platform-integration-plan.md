# 办公软件平台同步规划（飞书优先，平台可插拔）

> 状态：**规划**（尚未实现）。本文冻结目标架构与装配参数；实现以代码与
> 测试为准。工作台数据同步已按**会话级**落地（切换会话即切换工作台，
> 不串数据），为群聊载体提供天然映射基础。

## 1. 目标

Seelex 会话与办公软件讨论群组（飞书群 / 钉钉群 / Slack 频道等）双向同步：
**一个会话运维一个功能或一个模块**，群组即会话。工作台（task/worktable）
按会话级隔离，切换到哪个会话就展示哪个模块的进度，天然适配“每个模块一个
讨论群”的组织方式。

## 2. 装配参数（开发者自主选择平台）

预留配置（`seelex.yaml` 或环境变量），允许开发者选择办公软件互动平台：

```yaml
office:
  integration:
    platform: none        # none | feishu | dingtalk | slack | …
    app_id: ""            # 平台应用凭据（只经配置注入，不落日志）
    app_secret_env: ""    # 指向环境变量名，避免明文配置
    group_scope: ""       # 可选：限定参与同步的群 ID 白名单
    session_binding: auto # auto | manual：会话 ↔ 群聊绑定方式
```

实现上定义 `office.Transport` 端口（订阅事件 / 发消息 / 拉成员 / 投票查询），
各平台 adapter 实现该端口；`none` = 关闭，不影响现有 TUI/GUI。

## 3. 会话 ↔ 群聊映射

- `session_id ↔ 群聊/thread ID` 双向绑定（持久化进 SessionRecord 元数据）。
- 会话级工作台数据随会话切换整体替换（已实现
  `SwitchSessionTasks`：清空旧会话 task、恢复目标会话 task，子代理树同步
  清空）——群聊场景下切群 = 切会话 = 切工作台。
- 群内消息经 adapter → Application `Submit`；进度/打点经事件 → 群内摘要推送。

## 4. 策略：会话内容总结 → 授权动作（用户后续补充细化）

计划中的动作门禁策略：

1. **会话内容总结**：办公平台侧先提供“会话内容总结”能力。
2. **提示词生成**：总结 agent 经 harness 系统提示词，产出适合 coding agent
   执行的提示词（只传结构化任务，不污染 coding agent 的 prompt 格式——
   复用 B6“只装配 task_id/结论、不注入过程内容”的原则）。
3. **动作门禁**：执行前必须等待**有权限人员同意**，或通过**投票 ≥ 2/3
   认可**后才开始动作；不满足则只出方案不出手。

该策略的具体参数（谁有权限、投票窗口、超时、结果回传格式）由后续策略
补充，本文只冻结方向。

## 5. 阶段计划

| 阶段 | 内容 | 状态 |
|---|---|---|
| P0 | 装配参数 + `office.Transport` 端口抽象（`none` 默认） | 规划 |
| P1 | 飞书 adapter：事件订阅、消息收发、会话↔群映射 | 规划 |
| P2 | 会话内容总结 agent + harness 提示词产出 | 规划 |
| P3 | 授权/投票门禁（人工同意或 ≥2/3 投票） | 规划 |
| P4 | 其他平台（钉钉/Slack）adapter | 规划 |

## 6. 安全与隐私边界

- 凭据只经配置/环境变量注入，不落日志、不进 Snapshot、不进 prompt。
- 群成员角色映射到 Seelex 权限模型；群内消息按会话隔离，不跨会话泄露。
- 自动动作始终受 P3 门禁约束；只读同步（进度推送）不受门禁限制。
