# DeepSeek-V4.1-Flash 名称与接入方式调研

> 调研日期：2026-09-11
> 范围：DeepSeek-V4.1-Flash 的 API 名称、Codex 接入方式、开源自托管可行性
> 结论状态标记：本文所有结论均标注为「已核实（官方文档）」或「实测（本机）」两类来源。

## 0. 结论摘要

1. **API 名称只有一个：`deepseek-flash`。** 不存在 `deepseek-v4.1-flash` 这个 model 取值；
   版本号 `V4.1-Flash` 是「模型版本」，不是「API 名」。
2. **旧名仍可用但已退役**：`deepseek-v4-flash`、`deepseek-v4-flash-vision-exp` 会被路由到
   V4.1-Flash，并按 Flash 计费；`deepseek-v4-pro` 自 2026-09-14 12:00（北京时间）起同样被路由到
   V4.1-Flash。
3. **Codex 有官方接入页**（含一键脚本与手写配置字段参考），已实现能力强于手工猜测：官方
   catalog 把 `deepseek-flash` 的 `input_modalities` 声明为 `["text","image"]`，即 Codex 可直接
   把图片（含截图）作为输入交给该模型。
4. **开源自托管属集群级项目**：权重与技术报告已发布，但官方原文是「将与开源社区推进
   V4.1-Flash 推理支持」，公开文本中出现的是「2000+ GPU 规模部署」的招商表述，不构成单机/工作站
   可部署的结论。
5. **本机网络实测限制**：`huggingface.co` 直连不可达（HTTP 000），`hf-mirror.com` 可达（HTTP 200）；
   `developers.openai.com` / `platform.openai.com` 返回 403，因此本文不引用 OpenAI 侧文档。

## 1. 名称事实

### 1.1 官方 Models & Pricing 表（已核实）

来源：<https://api-docs.deepseek.com/quick_start/pricing>

| 维度 | `deepseek-flash` | `deepseek-v4-pro` |
|---|---|---|
| 模型版本 | DeepSeek-V4.1-Flash | DeepSeek-V4-Pro-0813 |
| 上下文 | 1M | 1M |
| 最大输出 | 384K | 384K |
| 思考模式 | 支持（默认开启） | 支持 |
| Responses API | 支持 | 支持 |
| Anthropic API | 支持 | 支持 |
| Vision | 支持 | 不支持 |

表注原文要点：

- 注(1)：「Use `deepseek-flash` as the model name. The legacy names `deepseek-v4-flash` and
  `deepseek-v4-flash-vision-exp` are still accepted, but the corresponding models have been
  retired, their requests are served by the DeepSeek-V4.1-Flash model and billed at the Flash price.」
- 注(2)：V4.1 Flash 在性能、成本、速度与总耗时上全面超过 V4 Pro，V4 Pro 将有序退役；自
  2026-09-14 12:00（北京时间）起 `deepseek-v4-pro` 的请求全部路由到 V4.1 Flash 并按 Flash 计费。

### 1.2 官方发布公告（已核实）

来源：<https://api-docs.deepseek.com/news/news260910>

- 「Set your model to `deepseek-flash`.」
- 「V4-Flash & V4-Flash-Vision-Exp are retired. For compatibility, `deepseek-v4-flash` and
  `deepseek-v4-flash-vision-exp` temporarily route to V4.1-Flash.」
- 「V4.1-Flash is now live on the DeepSeek API with native multimodal support.」
- 架构：552B 参数 MoE，非对称 Causal Encoder–Decoder，输入 8B 激活 / 输出 16B 激活；
  KV cache 相比上一代降到 1/4 HBM、1/8 SSD 存储占用。
- 官方列出的 agent 伙伴：WorkBuddy（含 CodeBuddy）与 OpenCode 已支持 V4.1-Flash。
- 开放权重：<https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash>，技术报告
  `DeepSeek_V41_Tech_Report.pdf` 同仓库。

### 1.3 Lists Models 的官方取值（已核实）

来源：<https://api-docs.deepseek.com/api/list-models>

官方示例响应只含两个 id：`deepseek-flash`、`deepseek-v4-pro`。

### 1.4 本机实测证据

以下为本次调研在本机对 `https://api.deepseek.com` 的真实调用结果（凭据来自本机 Codex 配置，
不落盘、不外泄）：

| 探测 | 结果 |
|---|---|
| `GET /models` | 200，data = `deepseek-flash`、`deepseek-v4-pro` |
| `POST /responses` model=`deepseek-v4.1-flash` | 400，`The supported API model names are deepseek-flash, deepseek-v4-pro, but you passed deepseek-v4.1-flash.` |
| `POST /responses` model=`deepseek-v4-flash` | 200，响应 `model` 字段回写为 `deepseek-flash`（证实旧名被路由） |
| `POST /responses` model=`deepseek-flash` + 图像输入 | 200，模型正确描述「红底白色圆形」测试图（证实视觉链路可用） |

结论：**只要写 `deepseek-flash`**。写带版本点的名字会直接 400。

## 2. 接入路径 A：官方 API（本机已落地）

### 2.1 官方一键脚本（Windows）

来源：<https://api-docs.deepseek.com/quick_start/agent_integrations/codex>

```powershell
irm https://cdn.deepseek.com/api-docs/codex-deepseek-setup-en.ps1 | iex
```

脚本当前版本 `1.3.0`（脚本头部自带版本号），行为要点：备份 `~/.codex/config.toml` 到
`~/.codex/backup-deepseek/`；写入 `~/.codex/models.json`；只重写必要字段并保留 MCP、项目信任等
既有配置；写盘前做语法校验；菜单项 1 = `deepseek-flash`（接受图像输入），2 = `deepseek-v4-pro`，
9 = 还原默认配置；重跑脚本会清理旧版脚本写入的 `deepseek-v4-flash*` 条目。

注意：该命令是「下载即执行」，会改写用户目录配置。本文调研只下载脚本本体做比对，未执行它。

### 2.2 官方手写配置（字段参考）

官方给出的 `~/.codex/config.toml` 等价内容：

```toml
model = "deepseek-flash"
model_provider = "deepseek"
preferred_auth_method = "apikey"
forced_login_method = "api"
model_reasoning_effort = "high"
web_search = "disabled"
model_catalog_json = "~/.codex/models.json"

[model_providers.deepseek]
name = "deepseek"
base_url = "https://api.deepseek.com/"
wire_api = "responses"
experimental_bearer_token = "<your DeepSeek API Key>"
```

字段语义（官方字段参考）：`wire_api = "responses"` 表示走 Responses API；`web_search` 对 DeepSeek
模型关闭内置联网；`model_catalog_json` 指向自定义 catalog，Codex 从它读取上下文窗口、推理档位、
工具调用格式等元数据。

### 2.3 本机当前状态

本机 `~/.codex` 已按上述官方口径对齐（改动前已备份为同目录 `*.bak-<时间戳>`）：

- `config.toml`：`model = "deepseek-flash"`，provider 为 `deepseek`，base_url
  `https://api.deepseek.com/`，`wire_api = "responses"`，已补 `web_search = "disabled"`。
- `models.json`：`deepseek-flash` 条目与官方脚本写入的 catalog **逐字段一致**（含
  `input_modalities = ["text","image"]`、`supports_image_detail_original = true`、
  `context_window = 1048576`）。

已知与官方的两处差异（均为本机环境既有事实，非本次改动引入）：

1. 本机 Codex CLI 为 `0.147.0`，`--strict-config` 会报 `preferred_auth_method` 与
   `forced_login_method` 为未知字段（普通启动忽略未知字段，不影响运行）；这两个字段是较新版本
   Codex 的取值，按官方文档保留即可，升级后自然生效。
2. `deepseek-v4-pro` 条目的 `supports_search_tool` 本机为 `true`，官方 catalog 为 `false`；该模型
   将于 2026-09-14 起被路由到 V4.1-Flash，影响面小，未改动。

### 2.4 验证记录

```text
codex exec -m deepseek-flash -s read-only --ephemeral --skip-git-repo-check --strict-config "Reply with exactly one word: pong"
```

结果：启动横幅 `model: deepseek-flash` / `provider: deepseek`，模型返回 `pong`，即 catalog 命中、
provider 路由与 Responses API 链路均可用。图像能力另由 §1.4 的直接 API 调用验证。

### 2.5 其他 agent 的对照（仅供参考）

- Claude Code（官方页）：`ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic`，
  `ANTHROPIC_MODEL=deepseek-flash[1m]`（注意 `[1m]` 后缀是 Claude Code 侧的 1M 上下文写法，不是
  DeepSeek API 的 model 名）。
- OpenCode（官方页）：`/connect` → provider `deepseek` → API Key → 选择 DeepSeek-V4-Flash。

## 3. 接入路径 B：开源自托管

事实（官方公告 + 权重页）：

- 权重仓库：<https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash>；技术报告同仓库。
- 规模：552B MoE，输入 8B / 输出 16B 激活参数，1M 上下文 —— 即便激活参数很小，权重与 KV 仍需
  多卡多机显存与高速互连。
- 官方表述：「We'll work closely with the open-source community on V4.1-Flash inference support
  and explore more deployment options. Planning a large-scale deployment with 2,000 GPUs + a
  storage cluster? Let's talk.」——即社区推理支持仍在推进，官方对外口径是集群级部署。

本机网络可达性（2026-09-11 实测）：

| 目标 | 结果 |
|---|---|
| `https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash` | HTTP 000（直连不可达） |
| `https://hf-mirror.com/deepseek-ai/DeepSeek-V4.1-Flash` | HTTP 200（镜像可达） |

结论：**当前可行的部署形态是「用官方 API」**；自托管需要另行评估硬件与推理框架支持，不应在单机
工作站或本地开发环境上做可行性假设。
