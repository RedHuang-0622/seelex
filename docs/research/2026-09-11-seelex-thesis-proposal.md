## 一、选题背景与研究意义

### 1.1 研究背景

**（1）从"生成代码"到"完成工程任务"的范式迁移**

自 2022 年思维链提示（Chain-of-Thought Prompting）[1] 证明大语言模型（Large Language Model, LLM）具备可被显式引导的多步推理能力以来，LLM 在软件工程中的定位发生了两级跃迁：第一级是从"语法补全"走向"意图级代码生成"，第二级是从"生成一段代码"走向"自主完成一项工程任务"。ReAct [2] 提出以"推理—行动—观察"交错闭环替代纯文本推理，把 LLM 的输出从"答案"变成了"动作"；此后，工具调用（Toolformer [4]、ToolLLM [5]）、可执行代码即动作空间（CodeAct [6]）、以及把编译器/测试/终端纳入动作空间的智能体（SWE-agent [11]）逐步把 LLM 从"对话者"改造成"执行者"。

这一迁移在评测上留下了清晰刻度。SWE-bench [10] 首次把评测对象从"函数级代码补全"换成"真实 GitHub 仓库中的 issue 修复"，要求模型在真实代码库中定位缺陷、修改跨文件代码并通过仓库既有测试。这类任务的成功不取决于单次生成质量，而取决于**模型之外的一整套执行基础设施**：如何在有限上下文里呈现仓库、如何让工具调用安全且可回滚、如何在多步失败后恢复、如何把长任务拆成可并行的子任务。

**（2）Harness 成为决定成败的关键变量**

在工程实践中逐渐形成共识：模型能力是上游变量，而"包裹模型的执行框架"（Agent Harness / Agentic Runtime）是产品能力的实际边界。一个可用的编码智能体必须回答六个问题：

1. 模型在什么时机可以看到哪些工具？
2. 文件与 Shell 操作如何被限制在合法工作区内？
3. 长任务如何被拆分、并行执行并把结果合并回主会话？
4. 上下文超出预算时，哪些内容保留、压缩或按需读回？
5. 会话、计划与工具结果如何在进程重启后可靠恢复？
6. 多个模型、账号、插件与外部工具如何在运行时安全切换？

这六个问题构成了 Harness 的完整语义边界，也暴露了当前主流方案的结构性矛盾：

- **上下文不可逆**：多数框架在触发压缩后只保留摘要，被压缩的原始证据不可读回，导致模型无法回溯"自己此前究竟看到了什么"，压缩本身成为不可审计的黑箱 [13][15]。
- **多智能体编排缺乏证据契约**：多智能体研究 [7][8][9][16] 证明协作能带来增益，但父子智能体之间究竟继承什么、回传什么、如何去重与溯源，多数实现停留在"把父对话复制一份"的工程直觉层面。
- **安全边界单薄**：不少实现依赖系统提示词约束模型"不要访问项目外文件"，或使用粗粒度沙箱；缺少"物理路径边界"与"策略审批边界"的分层。
- **评测与生产割裂**：以真实 LLM 与真实网络为中心的测试不可复现、不可离线运行，导致 CI 无法为 Tool Calling、审批与编排路径提供回归保护。
- **闭源与模型绑定**：主流商业编码智能体多为闭源且绑定特定模型与云服务，研究者难以复现内部机制，团队也难以满足数据主权与合规审计要求。

Seelex 正是针对上述矛盾的工程回应：一个开源、本地优先、多模型可路由、上下文可逆治理的 Coding Agent Harness。截至本开题，项目已完成从运行时原语到产品前端的贯通实现，但仍处于 Developer Alpha：跨进程 Agent 间协议尚未实现、缺少标准化编码基准结果、前端交互测试覆盖率偏低（TUI 覆盖率低于核心编排层）。把这些"已知缺口"转化为可验证的研究问题，正是本课题的起点。

### 1.2 研究意义

**理论意义**

1. **把"上下文"从工程直觉提升为可计算的资源模型**。本课题将上下文建模为一条"预算驱动的流水线"（组装 → 工具结果处理 → 压缩 → 控制器），给出可复算的预算公式、压缩阈值与窗口推导规则，使"上下文够不够"从经验判断变为可测量、可回归的工程量，为长任务智能体的上下文治理提供形式化参照。
2. **为父子智能体的证据传递建立结构化契约**。本课题把父子 Agent 间的上下文传递建模为"结构化快照 + 预算压缩 + 语义合并"三步，明确 finding / decision / constraint / progress 四类字段在合并时的差异语义（追加、替换、去重），使多智能体协作从"复制对话"走向可验证的状态演化。
3. **为智能体执行提供事件投影式的可审计模型**。本课题以"快照为权威状态、事件为增量同步"的协议描述智能体的可观测性，使每一次工具调用、审批与计划节点状态迁移都可被外部重放与审计，为智能体的可解释性研究提供系统级样本。

**工程与实践意义**

4. **给出可运行、可替换、可测试的开源参考实现**。课题以端口—适配器架构隔离"模型如何执行"与"产品如何解释执行结果"，使得上游运行时（Seele）、应用语义层与前端可以独立演进，避免能力被锁死在单一前端或单一 Agent 循环中。
5. **回应数据主权与成本可控的真实需求**。通过本地优先部署、项目级路径约束、逐操作人工审批与多账号池路由，课题为"代码不出内网、成本可归集、执行可回溯"的场景提供可落地的工程路径。
6. **沉淀可复用的验证方法论**。课题主张测试 Harness 与生产 Harness 共用同一套应用契约，用确定性脚本引擎替代真实 LLM 构造端到端用户旅程，使编排、审批与协议路径可以在无网络、无密钥的 CI 中回归验证。

## 二、国内外研究现状

### 2.1 国外研究现状

**（1）推理与行动范式**。Chain-of-Thought Prompting [1] 揭示了显式中间推理对复杂任务的增益；ReAct [2] 进一步把推理轨迹与动作执行交错，形成"思考—调用工具—观察结果—再思考"的闭环，成为当前几乎所有编码智能体的默认执行骨架。Reflexion [3] 引入语言化的自我反思与情节记忆，使智能体在失败后能基于历史反馈修正策略，把"一次执行"扩展为"可迭代的自我改进"。

**（2）工具使用与动作空间设计**。Toolformer [4] 证明模型可通过自监督方式学会调用外部 API；ToolLLM [5] 把工具规模扩展到 16000+ 真实 API，并给出面向多工具组合的规划与评测方案。CodeAct [6] 提出以"可执行 Python 代码"统一表达动作空间，相比 JSON 结构化调用具备更强的组合能力与自纠错空间。SWE-agent [11] 的关键贡献在于指出"智能体—计算机接口"（Agent-Computer Interface）本身是性能变量：为仓库级任务定制的文件查看、编辑与搜索接口，显著优于把通用 Shell 直接交给模型。

**（3）多智能体协作与编排**。Generative Agents [7] 展示了具备记忆流与反思机制的群体智能体行为；AutoGen [8] 把多智能体协作抽象为可编程的会话计算，提出可对话智能体与群聊协调者模型；MetaGPT [9] 把标准作业程序（SOP）编码进多角色流水线，验证了角色分工对复杂工程任务的增益。综述性工作 [16] 系统梳理了 LLM 多智能体在协作机制、拓扑结构与评测上的进展与挑战，并指出"通信开销、错误传播与状态一致性"仍是开放问题。

**（4）上下文工程与记忆**。`Lost in the Middle' [13] 通过受控实验揭示长上下文中的位置偏差：关键信息位于上下文中部时模型利用率显著下降，为"滑动窗口 + 优先保留最新轮次"的策略提供了实证依据。MemGPT [14] 借用操作系统的虚拟内存隐喻，把上下文管理抽象为分层记忆与主动换页，使智能体可在有限窗口下维持长期记忆。近年的上下文工程综述 [15] 把上下文从"提示词拼接"扩展为包含文本、环境状态、工具结果与记忆的统一工程对象，并系统整理了检索、压缩与结构化组织三类手段。

**（5）软件工程智能体与评测基准**。SWE-bench [10] 确立了以真实仓库 issue 修复为核心的评测范式，成为编码智能体能力的公共标尺；软件工程智能体综述 [12] 系统梳理了需求、编码、测试、调试、维护各阶段中 LLM 智能体的方法谱系，并指出"缺乏过程可审计性与端到端可复现性"是当前的共性短板。

**（6）协议与互操作生态**。模型上下文协议（Model Context Protocol, MCP）[17] 定义了智能体与外部工具/数据源之间的连接契约，使工具接入从"逐项目硬编码"转向"服务化声明"；智能体互操作协议（Agent2Agent, A2A）[18] 定义了跨组织智能体之间的能力发现（Agent Card）、任务生命周期与消息/产物语义。两者互补：MCP 解决"智能体—工具"，A2A 解决"智能体—智能体"。

### 2.2 国内研究现状

国内研究呈现"综述体系化、产业白皮书丰富、工程化落地快"的特点。在智能体体系结构方面，郭先会等 [19] 系统梳理了基于大语言模型的智能体构建方法，把任务规划、工具使用与记忆机制归纳为智能体的三大支撑能力；赵鑫等 [20] 在教材层面对大语言模型的基础理论、训练算法、使用范式与评测方法做了体系化梳理，为工程实现提供了统一的概念框架。在软件工程与智能体交叉方向，张犬俊等 [21] 对"大模型时代的软件工程"做了现状与展望式的综述，讨论了 LLM 对需求、设计、编码、测试、运维全流程的影响；彭鑫 [22] 从软件智能化开发的角度提出了对大模型赋能软件开发的定位、风险与演进路径的判断。在产业与标准层面，中国信息通信研究院 [23]、中国软件评测中心 [24]、中国人工智能学会 [25]、深圳市人工智能行业协会 [26] 等机构连续发布大模型技术与产业发展报告，为算力、模型、应用与治理提供了年度基线；中移智库 [27] 则针对提示工程这一直接决定智能体行为质量的环节给出了工程实践报告。

同时应当指出，国内工作多以综述、能力评估与产业观察为主，**面向"可运行、可复现、可审计的编码智能体运行时"的系统级开源实现仍然稀缺**；国产开源模型（如 DeepSeek 系列）大幅降低了 Harness 的接入成本与调用成本，使"多模型可路由的本地 Harness"首次具备现实可行性。

### 2.3 研究述评与本课题切入点

综合国内外现状，可以归纳出五个尚未被充分解决的问题，它们构成本课题的直接切入点：

1. **上下文压缩不可逆、不可审计**。现有压缩手段普遍以"摘要替换原文"为终点 [13][14][15]，被压缩内容无法按需读回，长任务在压缩点前后出现事实断裂。
2. **多智能体编排缺少证据契约与可视化**。协作机制研究 [7][8][9][16] 证明了增益，但"父子智能体继承什么、回传什么、如何去重溯源"缺少结构化定义；编排过程对用户不可见，出现异常时无法定位到具体节点。
3. **安全边界层次不足**。多数实现要么依赖提示词约定，要么只提供粗粒度沙箱，缺少"物理路径边界（能否逃出项目目录）"与"策略审批边界（项目内哪些操作仍需人工确认）"的分层设计。
4. **测试与生产的契约割裂**。编排、审批、协议路径缺少无需真实 LLM 即可确定性复现的端到端验证手段，导致 CI 无法为这些高风险路径提供回归保护。
5. **闭源与单一模型绑定**。主流商业方案难以复现内部机制，也无法满足数据主权、成本归集与合规审计需求；国内相关工作以综述与评估为主，缺少系统级开源实现。

**本课题定位**：不做模型训练、不做云端执行环境、不做 IDE 插件正面竞争，而是聚焦"Harness 层的治理能力"——把可逆上下文、结构化多智能体编排、双层安全边界、事务式扩展系统与事件投影可观测性，做成一个可运行、可测试、可替换、可自托管的开源实现，并以 Seelex 为工程载体交付与验证。

## 三、研究目标与研究内容

### 3.1 研究目标

设计并实现一个面向软件工程任务的开源 Coding Agent Harness，使其在**单进程本地运行**的前提下同时具备六项能力：① 项目作用域的工具调用与逐操作审批；② 按需加载的多智能体工作流编排；③ 预算驱动且可逆的上下文治理；④ 事务式的插件/Skill/MCP 扩展切换；⑤ 可恢复、可审计的持久化与可观测协议；⑥ 可离线、确定性复现的验证体系。最终以可运行的 TUI 与桌面 GUI 双前端，以及三平台 CI 通过的工程基线作为交付证据。

### 3.2 研究内容

**内容一：分层架构与端口化边界设计**
建立"运行时原语层（Seele）—防腐适配层（seelebridge）—应用语义层（application）—前端（TUI/GUI）"的四层结构。应用层以消费方定义的端口（Runtime / Session / Plugin / Workspace 等）声明依赖，由适配器实现；上游类型变化被限制在防腐层内，前端只消费应用层 DTO、Snapshot 与 Event。目标是把"模型如何执行"与"产品如何解释执行结果"解耦为可独立演进的模块边界。

**内容二：双执行路径（ReAct 默认 + 可选 DAG 编排）**
不以"强制规划"作为所有请求的前置条件：简单任务直接进入主 ReAct 闭环以降低首 token 延迟与计划 token 成本；复杂任务由模型按需加载工作流 DAG（JSON 规范化 + 字段归一化 + 节点引用/边/拓扑校验 + 环检测 + 拓扑排序 + Effort 策略约束）。研究重点在于"何时值得规划"的成本—收益边界，以及 DAG 校验失败时的降级行为。

**内容三：预算驱动的可逆上下文流水线**
把上下文处理实现为可组合组件链：`组装器 → 工具结果处理器 → 压缩器 → 上下文控制器`。核心设计包括：从模型上下文窗口中扣除输出预留与 12.5% 安全余量后计算输入预算；System Prompt 与当前工作栈不参与历史压缩；最新 N 轮保留原文，仅压缩滑动窗口之外的轮次；超大工具结果归档为不可变引用（`result_ref`），模型先看到有界摘要，需要时通过读回工具按需取回；压缩帧保留原始消息的可逆寻址，支持事后读回与审计。

**内容四：多智能体编排与父子证据承袭/合并**
每个 DAG 节点获得独立会话、节点作用域、提示块、账号绑定与 token 预算；父上下文在执行前导出为结构化快照（目标、父目标、决策、发现、进度、约束、待办、逃逸信息），经按预算压缩后作为证据块注入子节点；子节点产出按合并语义回传（发现与决策追加、进度替换、约束去重、token 累计）。研究重点是并行分支的状态隔离（避免多分支争用同一可变状态）与合并结果的来源可追溯性。

**内容五：双层安全边界与人机协同审批**
第一层为**物理边界**：所有文件与 Shell 工具先把目标解析为规范化绝对路径，并验证其仍位于绑定工作区根目录内。第二层为**策略边界**：在合法范围内进一步计算允许 / 询问 / 拒绝，默认采用"白名单外审批"模式，并支持显式放开。研究重点是两层边界不可互相替代的语义，以及隐藏工具即使被模型构造出调用也必须被拒绝的执行时校验。

**内容六：事务式扩展系统与账号池路由**
把插件定义为同时影响工具可见性、系统提示、技能可见性与 MCP 服务器的能力集合，切换按"准备 → 切换 → 清理"顺序执行，任一步失败按逆序回滚；工具可见性以请求级快照传入运行时，避免正在执行的请求观察到"一半新、一半旧"的能力集合。账号按角色（主智能体 / 子智能体 / 规划）分组进入池，分支使用角色与分支标识的确定性哈希选路，流式请求把租约保持到流结束。

**内容七：持久化与 Snapshot/Event 可观测协议**
应用层快照是权威状态，事件只负责增量同步：客户端启动读取完整快照，随后消费带序号/修订号的有序事件；事件缺口或协议不兼容时重新加载快照。持久化采用按项目分区、按会话隔离的追加式事件行与分片，模块 head 仅在新数据完整写入后原子发布，保证读者只能看到完整水位的内容。

**内容八：确定性验证体系与性能基线**
以脚本化引擎、固定装置、事件记录器与同一套应用端口构造不依赖真实 LLM、外部网络与密钥的端到端用户旅程，覆盖提交、工具生命周期、审批交互、快照/事件与最终可观察结果；真实模型冒烟测试保持显式启用，避免把 API 可用性误认为代码正确性。同时建立基于真实 TUI 全链路的性能与 token 成本基线。

## 四、拟解决的关键问题与创新点

### 4.1 拟解决的关键问题

**问题一：上下文预算与信息保真的平衡。** 在"必须压缩"与"不能丢失可回溯证据"之间建立确定边界——压缩发生在窗口之外、压缩目标为预算的 60%、并保留原始内容的可逆寻址；需要给出压缩预算的收敛判据，以及在压缩失败时的显式降级与上报路径。

**问题二：并行多智能体的状态隔离与合并一致性。** 多个分支并行执行时，对共享的会话上下文、项目知识与账号租约的读写必须互不串台；合并回父上下文时，需要对四类语义字段做差异化处理并保持来源标识，避免"最后写入者获胜"导致的证据丢失。需要以并发评审与竞态测试作为验证手段。

**问题三：安全边界的可证明性。** 需要论证路径规范化 + 根目录包含性检查能够抵抗符号链接、相对路径与工作目录切换造成的逃逸，并论证策略层与物理层的职责不可互相替代；同时保证工具可见性过滤在请求级生效，隐藏工具不可被构造调用绕过。

**问题四：可审计性与过程可解释性。** 需要把"用户看到的结果"与"运行时发生的事实"分离保存：可见对话记录、provider 历史、追加式执行事件、计划状态与不可变工具结果各自独立，使得计划节点、标题、工具来源与压缩检查点可以独立演进而不互相覆盖。需要给出计划节点级的事件投影与前端还原方案。

**问题五（诚实标注的开放问题）：跨进程智能体互操作与语义检索。** 当前编排仍为单进程内多节点会话，尚未实现跨进程/跨组织的协议化互操作；压缩历史的检索仍为"已知引用才能读回"的拉取式，缺少语义检索入口。两项将作为本课题的后续演进方向与研究边界声明，不在本期交付承诺之内。

### 4.2 创新点

**创新点一：可逆的上下文压缩与引用式工具结果外化。** 与主流"摘要替换原文"的不可逆压缩不同，本课题把压缩帧的原始消息保留为可寻址对象，使模型与审计者可事后读回；超大工具结果以不可变引用 + 有界摘要 + 按需读回的"三段式"取代简单截断。该设计把上下文治理从"节省 token"提升为"在成本、可审计性与任务连续性之间保持确定边界"。

**创新点二：以结构化快照为契约的父子智能体证据承袭与合并。** 把父子 Agent 之间的上下文传递从"复制对话"改为"结构化快照 + 预算压缩 + 语义合并"，并明确四类字段的差异化合并语义，使多智能体协作的中间状态可校验、可去重、可溯源。

**创新点三：物理边界与策略边界分离的双层安全模型。** 将"能否逃出项目目录"与"项目内哪些操作仍需人工确认"拆分为两个不可互相替代的边界，配合请求级工具可见性快照，使权限模型同时具备可解释性与可回归性。

**创新点四：测试 Harness 与生产 Harness 共用契约的确定性验证方法。** 以脚本化引擎替代真实 LLM 构造确定性端到端旅程，使编排、审批、快照/事件与工具生命周期路径可在离线 CI 中重复验证，克服"智能体系统难以回归测试"的共性困难。

**创新点五：事务式能力切换的运行时模型。** 把插件切换从"修改一个当前字段"提升为"准备—切换—清理"的事务，并保证切换期间飞行中的请求看到自洽的能力集合，为智能体的"专业形态切换"提供正确性保障。

### 5.2 关键技术方案

**（1）上下文预算与窗口推导。** 输入预算 = 模型上下文窗口 − 输出预留 − 安全余量（窗口的 12.5%）；软阈 75%、硬阈 90%、压缩目标 60%；滑动窗口轮次 N = clamp((上下文预算 × 比例 − 预留) ÷ 平均轮次 token, 4, 40)，比例默认 0.7；仅压缩窗口之外的轮次。实现上以脚本感知的 token 估算为基准，并引入基于 provider 用量反馈的校准因子（EMA 修正），使窗口决策、压缩预算与归档阈值使用同源计数。

**（2）工具结果外化。** 单条工具结果超过字符预算（默认 20000 字符，可配置）时归档为不可变引用，模型侧只保留有界摘要与省略提示；错误结果原样透传不做截断，避免错误信息被摘要掩盖。

**（3）多智能体执行与合并。** 计划节点执行时注入节点作用域与节点级提示块（节点目标 / 父证据 / 节点预算），并为每个节点创建独立会话；并行分支由协调器以信号量限流（默认最大并发 3），采用父快照克隆实现分支上下文隔离，并发出排队/开始/完成/失败/取消/崩溃生命周期事件；子节点结果经合并语义回传父会话邮箱，避免在计划锁内反向写引擎。

**（4）安全边界。** 文件与 Shell 工具统一经过"规范化绝对路径 → 根目录包含性校验 → 策略判定（允许/询问/拒绝）"的链路；默认"白名单外审批"，审批通过人机交互通道完成；工具可见性以请求级快照注入，隐藏工具的构造调用在执行时被拒绝。

**（5）扩展系统与账号路由。** 插件以声明式清单描述工具包含/排除、系统提示、技能与 MCP 服务器；切换采用准备/切换/清理三步并支持逆序回滚；账号池按角色与分支确定性哈希选路，支持显式绑定；流式请求保持租约至流结束。

**（6）持久化与可观测。** 事件行按固定规模分片追加，模块 head 原子发布；快照/事件协议带序号与修订号，缺口即触发客户端重载；计划节点、工具调用与 MCP 调用轨迹均有事件投影，供 UI 还原执行时间线。

### 5.3 实验与验证方案

| 验证维度 | 验证方法 | 判定依据 |
|---|---|---|
| 功能正确性 | `go build ./...`、`go vet ./...`、`go test ./...` 单元与集成测试 | 全仓与关键包测试通过 |
| 编排正确性 | 确定性端到端场景（脚本化引擎，无真实 LLM） | 提交、工具生命周期、审批、快照/事件、终态可观察结果符合预期 |
| 并发与隔离 | 并行计划运行的竞态测试与并发评审 | 无数据竞争；分支上下文与账号租约互不串台 |
| 上下文治理 | 预算/窗口/压缩阈值的单元与属性测试 + 压缩前后估算记录 | 窗口推导符合公式；压缩目标落在预算区间；读回内容与原帧一致 |
| 安全边界 | 路径逃逸用例集（相对路径、符号链接、工作目录切换）+ 隐藏工具构造调用 | 全部被拒绝；审批链可解释 |
| 前端协议 | GUI 协议测试与前端单元测试 | 快照/事件序列可被前端 reducer 正确还原 |
| 性能与成本 | 真实 TUI 全链路基准（同沙箱、同模型、同口径，多次采样） | 延迟分位数、吞吐、成功率、token 成本可复现 |
| 工程基线与兼容性 | Windows / Linux / macOS 三平台 CI，含竞态检测与覆盖率上传 | 三平台构建与测试全绿 |

## 六、可行性分析

**（1）技术可行性。** 项目已具备可运行基线：应用层、防腐层与上下文域均已落地；工作流 DAG 的加载、校验、并行执行与结果合并已在生产路径接线；插件事务切换、双层安全边界、快照/事件协议与三平台 CI 均已建立。本课题的增量工作是在既有基线上"补齐缺口 + 强化验证"，而非从零构建。

**（2）工程可行性。** 技术栈（Go 1.25.8、Bubble Tea、Wails、JSON 持久化）成熟稳定，构建与测试命令短小可复现；仓库无 vendor 第三方代码，依赖集中在上游运行时模块与少量通用库，供应链面可控。

**（3）条件可行性。** 开发仅需普通开发机与一个 OpenAI 兼容模型端点；离线验证路径不依赖真实模型与网络；真实模型冒烟测试保持显式启用，成本可控。

**（4）风险与对策。**

| 风险 | 表现 | 对策 |
|---|---|---|
| 上下文跨模块一致性漂移 | 新旧两套窗口/阈值策略并存导致行为不一致 | 收敛为单一上下文实现；过渡期加一致性测试护栏 |
| token 估算误差 | 保守估算在中文与长工具参数场景下偏差大 | 引入 provider 用量反馈校准；评估模型感知分词器接入 |
| 并行分支共享状态竞争 | 分支对同一状态存储的读写互相干扰 | 父快照克隆 + 节点作用域隔离 + 竞态回归测试 |
| 上游运行时依赖变动 | 依赖升级可能阻断构建 | 防腐层集中适配；依赖升级纳入 CI 回归 |
| 前端交互测试覆盖率偏低 | 前端回归保护弱于核心编排层 | 补齐前端协议测试，避免以全仓平均值掩盖前端缺口 |
| 标准基准缺失 | 尚无 SWE-bench / Terminal-Bench 类结果，横向可比性不足 | 本期建立可复现基准接入计划，明确标注"未完成"状态而非推算结论 |
| 范围蔓延 | 试图在期内同时完成跨进程协议与语义检索 | 明确列为后续演进方向，不在本期交付承诺内 |

## 八、预期成果与应用价值

**预期成果**

1. 一个可运行的开源 Coding Agent Harness，具备项目作用域工具调用、按需多智能体编排、可逆上下文治理、双层安全边界、事务式扩展系统与快照/事件可观测协议。
2. 一套确定性端到端验证体系与若干组可复现基准数据（功能、并发、性能、token 成本），可作为同类系统的对照基线。
3. 一份系统性的设计与实现技术报告（学位论文/技术报告），覆盖架构决策、关键算法与验证证据。
4. 可复用的垂直领域能力样板（以声明式插件形式组织工具、技能与外部服务），示范 Harness 的领域扩展路径。

**应用价值**

- 对个人开发者：在可控成本下获得可自托管的编码智能体，支持多模型路由与会话恢复。
- 对数据敏感型团队：以本地部署 + 路径约束 + 逐操作审批 + 事件审计满足合规与审计要求。
- 对研究与教学：提供可复现、可替换、可测试的智能体运行时样本，降低多智能体与上下文治理论文的工程复现门槛。
