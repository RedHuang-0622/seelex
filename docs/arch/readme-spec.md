# README 编写规范（模块文档约定）

日期：2026-08-22
状态：稳定约定（长期有效）
适用范围：仓库内所有 Go package 与可独立维护运行模块的 README；与
`AGENTS.md`「3. 模块 README 必备内容」「4. 写作和链接规则」配合使用。

## 1. 结构总纲（自上而下）

每个模块 README 依次覆盖（允许合并章节，但不得省略定位、边界、Review 与
验证）：

1. `## 生态位`（可并列"模块定位"）：一句话定位 + 主要调用方。
2. 职责与非职责：明确做什么、刻意不做什么。
3. 目录/文件结构：关键文件及职责；文件多时用分卷导航（见 §4）。
4. 核心实现：主要类型、接口、状态和算法。
5. 数据流或生命周期：输入如何到达、状态如何变化、输出给谁。
6. 依赖方向：允许依赖与禁止反向依赖。
7. 并发、存储、安全或错误语义：只写与模块相关的约束。
8. 扩展方式：新增实现时应修改的位置和兼容要求。
9. Review 指南：最容易出错的边界与审查问题。
10. 测试与验证：最小测试命令及关键测试文件。

README 只描述当前代码，不把规划写成既成事实；未来能力必须标注"规划/尚未
实现"并链接设计文档。

## 2. 生态位措辞统一

- 一律以 `## 生态位` 开头说明模块在生态中的位置与主要调用方；同一语义禁止
  混用"模块定位/生态位"两种标题。
- 先写结论和边界，再写实现细节；避免把源码逐行翻译成文档。
- 语言统一中文，代码标识符、命令、协议字段与文件名保留原文。

## 3. 文件与函数索引（自动生成）

- 每个模块 README 追加 `## 文件与函数索引`：逐文件列出每个函数（含测试
  函数）的**签名 + 首行摘要**；无 doc 注释的函数只列签名，不臆造说明。
- 摘要的唯一事实源是**源码 doc 注释**；索引由脚本从注释提取，改注释后重跑
  即可刷新，杜绝文档与代码两处漂移。
- 仓库生成器：`scripts/gen_core_readme_index.py`（覆盖 `application/core`
  根包分卷与叶子包）。其它包的 README 可复用同一提取逻辑（doc 首行 + 签名），
  保持格式一致。
- 索引条目语言统一中文；doc 注释首行缺中文时，先补齐中文注释再生成。

## 4. 按前缀分卷（仅根/大包）

- 单文件行数硬约束 ≤ 1000；文件数多（约 >15）的根包，README 按**文件前缀**
  分卷：每卷一个 `README-<卷名>.md`（含 `## 生态位` + 文件与函数索引），主
  README 保留生态位与「分卷 README」导航表（卷名 + 覆盖文件 + 一句话生态位）。
- 卷名用连字符（如 `work-table`）；文件前缀用下划线（如 `work_table.go`）时，
  生成器需显式映射"前缀 → 卷名"，避免匹配不到。
- 叶子包（文件少）维持单 README：生态位 + 文件与函数索引。

## 5. 链接与编码

- 使用相对链接，链接目标必须存在；不得使用本机绝对路径，不得暴露真实
  API key/token/password/DSN 或个人目录（详见 AGENTS.md §4）。
- 文件必须 UTF-8 无 BOM。**含中文的脚本必须落盘为 UTF-8 文件再执行**，禁止
  经 shell 管道内联中文（管道编码会把非 ASCII 替换成字面 `?`，写入乱码）；
  脚本内断言同样用 unicode 转义，避免依赖管道编码。
- 删除或移动模块时，同步修正上级 README、文档索引与 contract tests。

## 6. 验证

- `e2e/layout_test.go` 固化两条：模块目录必须有 README；README 内所有相对
  链接必须存在。文档改动后必须重跑 `go test ./e2e/ -count=1`。
- 提交前 `git diff --check`；Windows 工作树 CRLF + `core.autocrlf=true` 下
  `gofmt -w` 规范化不会产生 git 噪音。
