## 1. 单轮对话端到端延迟（25 样本，成功率 100%）

| 指标 | 数值 |
|---|---|
| P50 | **3.71 s** |
| P95 | **13.07 s** |
| P99 | 21.07 s |
| 平均值 | 5.81 s |
| 最小值 | 2.41 s |
| 最大值 | 23.59 s |

分布：多数样本 2.4–5.5 s；尾延迟由 3 个 12.9–13.1 s 与 1 个 23.6 s 构成（对应上游 API/网络抖动，见第 4 节）。

## 2. 工具调用端到端延迟（20 样本，成功率 100%，get_time 调用链）

| 指标 | 数值 |
|---|---|
| P50 | **4.30 s** |
| P95 | **16.31 s** |
| P99 | 22.21 s |
| 平均值 | 7.19 s |
| 最小值 | 3.48 s |
| 最大值 | 23.68 s |

工具链路子指标（来自 sessionstore 事件库，20 个会话精确时间戳）：

| 子指标 | P50 | P95 | 平均 | 最大 |
|---|---|---|---|---|
| 模型决策延迟（用户消息 → 发起工具调用） | 1.90 s | 13.28 s | 4.81 s | 19.27 s |
| 工具执行耗时（get_time） | 1.02 ms | 3.27 ms | 1.29 ms | 3.87 ms |

结论：工具本身的执行开销可忽略（毫秒级）；工具调用 E2E 延迟 ≈ 模型决策 + 生成延迟，瓶颈在上游 LLM。

## 3. QPS / 吞吐

| 场景 | 请求数 | 成功 | 总耗时 | 吞吐 | 平均单轮 |
|---|---|---|---|---|---|
| 串行（单会话连续 14 轮：10 对话 + 4 工具） | 14 | 14 (100%) | 48.7 s | **0.288 req/s（17.3 req/min）** | 3.48 s |
| 并发（2 个会话 × 2 轮，并行提交） | 4 | 4 (100%) | 14.9 s（含启动） | **0.269 req/s（16.2 req/min）** | 3.50 s |
| 并发纯处理窗口（排除会话冷启动） | — | — | 每轮 ~4.2 s 完成 2 请求 | ≈0.48 req/s（28.8 req/min） | — |

并发可扩展性观测（多轮尝试）：
- 2 会话并发：健康窗口内可维持，单轮 p50 ≈ 3.4 s，聚合吞吐约为串行的 1.7–2 倍（纯处理窗口）。
- 3 会话并发：多次触发上游 API 流式错误/超时（观测到 7/9、5/6、4/10 成功），并有 19.8 s 长尾，无法稳定维持聚合吞吐。瓶颈为上游 DeepSeek API 限流与稳定性，非本地引擎。

## 4. 观测到的关键事实与风险

1. **延迟构成**：E2E 延迟 ≈ 上游 LLM 决策+生成时间。本地引擎与工具执行对延迟贡献 < 10 ms。
2. **长尾根因**：P95 的 13–24 s 长尾来自上游 API/网络抖动。测试期间观测到 `lookup api.deepseek.com ... i/o timeout`（DNS 超时）与流式连接错误；同窗口 curl 探测 TTFB 正常（0.3–1 s），属间歇性 WSL 网络/上游波动。
3. **吞吐上限**：单会话串行稳定上限 ≈ 0.29 req/s（17 req/min）；提升并发受上游 API 限制，3 路并发即出现错误，不能作为容量扩展手段。
4. **冷启动开销**：每样本全新会话含进程启动 ~5 s 与首轮模型调用；串行 warm 会话单轮平均 3.48 s（排除首轮 13.3 s 冷启动后 2.0–3.4 s）。
