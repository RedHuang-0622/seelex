# 全局 computer-use 冒烟检查单（2026-10-01）

> **口径**：冒烟 = **computer use 把每个操作都试一遍**（不是"跑一遍用例"）。
> 每条 = 一次「动作 → 观察 → 判定」，判定看的是**画面/状态**，不是"命令 exit 0"。
> 删代码按轮次做（删一波 → 提交一次 → **本单跑一遍** → 没问题再删下一波，见
> `docs/devlog/2026-10-01-goal-board-vmodel-brief.md` §0 第 6 条）。

## 0. 为什么单列这份单

`go build` / `go vet` / 单元用例只能证明「没编译坏、没断言坏」。删死代码最典型的
事故形态不是编译失败，而是**删掉了一条没人调、但前端/冷恢复路径还在等的东西**——
编译全绿、用例全绿、界面上那块变空。所以删除轮次的验收必须是**界面点一遍**。

## 1. 前置（每次冒烟固定三步）

1. `go build ./...`（exit 0）。
2. 构建暂存二进制：`make stage-gui`（或 `SMOKE_TARGET=<二进制> make smoke-gui`）。
3. **起一个干净数据根**（别用正在跑的实例的数据根）：`SEELEX_DATA_ROOT=<tmp>` 起暂存
   二进制，避免与正在运行的主实例抢 `lock.owner`（`sessionstore/data_root_lock.go`）。

> **本轮的限制（如实记）**：当前机器上已有一个 Seelex 实例在跑，且**本会话就跑在它
> 里面**——重启它等于掐掉正在执行的这轮任务。所以本轮做的是
> **① 暂存二进制的无头冒烟 + ② 运行中实例的只读点检**，
> **③ 重启后的完整点检交给下一次启动**（按 §2 逐条打勾）。

## 2. 操作面（逐条点，逐条判）

### 2.1 会话轴

| # | 操作 | 判定 |
|---|---|---|
| S1 | 新建会话（`+`） | 进入 draft，会话列表出现新行、标题占位正常 |
| S2 | 切换会话 | 记录区切到目标会话；**不串味**（不出现别的会话的行） |
| S3 | 冷会话恢复（切到久未打开的会话） | 记录区不回退已压缩前缀；尾部消息完整 |
| S4 | 重命名/删除会话 | 列表即时更新；删除后不残留在列表 |
| S5 | 从会话分支出新会话 | 新会话出现且已切换，原会话不动 |

### 2.2 输入轴（composer）

| # | 操作 | 判定 |
|---|---|---|
| I1 | 普通发送 | 用户行出现、回复流式渲染 |
| I2 | 回合运行中再次提交（排队） | 输入进队列，队列行可见 |
| I3 | 排队输入「撤回」到输入框 | 输入框恢复该文本，队列行消失 |
| I4 | 排队输入调序 | 队列顺序按操作变化 |
| I5 | 中断（stop） | 流停止、状态回 idle、可继续输入 |
| I6 | 草稿落盘与恢复（写一半 → 切会话 → 切回） | 草稿原样回来 |
| I7 | `@` 召唤建议面 | 列出团队库条目，可选中 |
| I8 | `#` 插件 / `$` 技能符号 | 建议面按符号切换，选后提示为**信任注入**而非普通用户文本 |
| I9 | 附件 / 图片 | 图片进随图队列，下一次请求带上 |
| I10 | 斜杠命令（`/`） | 建议面列出命令；执行后状态可观察 |

### 2.3 右栏「工作台」轴

| # | 操作 | 判定 |
|---|---|---|
| W1 | 「目标」面板 | 有活跃 goal 时显示目标/轮次/座位；无 goal 时给入口提示（**不是空白**） |
| W2 | 工作表格入口 → 弹窗 | 弹窗只有一个标题、只有一个纵向滚轮、行区可独立滚动、分页可用 |
| W3 | 工作表格行内打点（todo 三态） | 状态即时更新，刷新后仍在新态 |
| W4 | 定时任务面板 | 常驻；任务名/类型/启用/下次运行/上次结果/日志尾部渲染 |
| W5 | 新建定时任务（含「创建后立即启用」开关） | 弹窗开关与文案一致；创建后列表出现 |
| W6 | 取消定时任务 | 任务从列表消失/标记取消 |

### 2.4 面板与页签轴

| # | 操作 | 判定 |
|---|---|---|
| P1 | 状态 / 概要 / 工作区 面板 | 渲染非空、无「undefined」字样 |
| P2 | 工作区文件树 → 文件预览 | 只读内容渲染；超大文件走预览截断 |
| P3 | 历史检索 | 检索有结果、命中可回读 |
| P4 | 进程面板：账户 / 插件 / 技能 / 定时任务 / 模型 | 各自列表非空、切换不崩 |
| P5 | 页签拖拽到另一栏互换 | 布局按操作变化，刷新后保持 |
| P6 | 各面板压缩/展开 | 压缩后内容面不残留、展开后完整 |

### 2.5 设置与权限轴

| # | 操作 | 判定 |
|---|---|---|
| G1 | 打开设置弹窗 | 弹窗封顶可自滚（内容多时不撑破屏幕） |
| G2 | 切皮肤 | 主题即时生效、刷新后保持 |
| G3 | 切模型 / 切账号 / 切插件 / 切 effort | 选择生效并在状态面可见 |

### 2.6 目标治理轴（本轮改动的重点面）

| # | 操作 | 判定 |
|---|---|---|
| T1 | 有活跃 goal 时的目标面板 | 轮次/当前座位/里程碑/步骤按只读投影渲染 |
| T2 | 无活跃 goal 时的目标面板 | 空态给入口提示，不显示上一次 goal 的残留 |
| T3 | 团队面板（成员/在编） | 成员生态位与档案完整；无「形态」残留（2026-10-01 已退场） |
| T4 | 治理回合失败时的可见面 | 面板显示「本轮治理未完成 + 原因」，而不是只有墙钟可猜 |

## 3. 判定与留痕

- 每条记 **通过 / 失败 / 未做**，失败附**截图引用**与「哪一步、期望什么、实际什么」。
- 未做的条目必须写清**为什么没做**（例如："需要重启实例，本轮不能重启"），
  不许用"未发现问题"代替"没做"。
- 结论写回当轮 devlog；**有失败就不进下一轮删除**（先修，再重跑本单）。
