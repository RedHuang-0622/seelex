# Qoder 皮肤 · 拟物交互模式设计（书签抽取 / 书本翻页 / 滑动 / 拉伸）

> 上游：`DESIGN-LANGUAGE.md`（视觉语言）+ `OPTIMIZATION-PLAN.md`（先把丑的拆掉，再谈动）
> 现状锚点：`gui/frontend/dist/motion.js` 已有一份动效契约（`prefersReducedMotion` / `rollNumber` /
> `bindHorizontalDragDelegate` / `bindScrollShadows`），本文**扩展**它，不另起一套。

---

## 0. 为什么先讲原则

拟物动画最容易变成"装饰性动画"——而 `DESIGN-LANGUAGE.md` 第 7 节把它列进了黑名单。
两者的分界线只有一条：

> **拟物 = 把一个"看不见的系统状态"变成"看得见的物理量"。**
> 如果说不出它表示哪个状态，它就是装饰，不做。

逐个对照：

| 动作 | 它表示的不可见状态 |
|---|---|
| 书签抽取 | "这条会话正在被搬去另一个位置"（会话的**归属**在变） |
| 书本翻页 | "当前视图是同一个会话的另一页"（视图的**层**在变） |
| 滑动 | "这个面板占多少空间"（布局的**量**在变） |
| 拉伸 | "这个区域还能长多高"（容量的**余量**） |

四条都能回答"它在说什么"。所以可以做。

---

## 1. 材质基座（四个动作共用的"物理"）

拟物最怕"四个动作像四个不同的 App"。所以先把材质钉死，四个动作只允许调"幅度"和"方向"。

### 1.1 场景里的物件

| 物件 | 对应 | 物理属性 |
|---|---|---|
| **桌面** | 顶栏 + 左栏 + 右栏（壳，承载 `--shell-gradient`） | **不可动**。任何动画都不许推它 |
| **纸** | 中栏内容区（`--surface` 纯白） | 零厚度，可翻页、可被替代 |
| **书签** | 左栏会话行（`.stack-button`） | 薄片，可抽出、可插回 |
| **抽屉** | 左栏 / 右栏整体 | 可推回柜体 |
| **弹性带** | 终端面板上沿、composer 高度 | 可拉伸，有阻力 |

> "桌面不可动"是这一节的硬约束。它直接延续 `DESIGN-LANGUAGE.md` 第 2 节：
> 壳是分层基座，不是演员。所以"翻页"只翻纸，不翻壳。

### 1.2 参数（全部走已有 token，不新增魔法数）

```css
/* 复用视觉语言的既有 token，不引入新阴影/新圆角——否则会把 P0-2/P0-3 拆掉的东西放回来 */
--skeu-lift:      var(--shadow);            /* 拿起时的影子：就是浮层那一档 */
--skeu-settle:    var(--dur-med) var(--ease-out);   /* 240ms，回弹统一用它 */
--skeu-enter:     var(--dur-fast) var(--ease-out);  /* 160ms，吸附统一用它 */
```

| 参数 | 值 | 说明 |
|---|---|---|
| 跟手比 | **1:1** | 指针走多少，物件走多少（超限后除外）。任何"拖了 10px 动了 3px"都是 bug |
| 起手阈值 | **4px** | 沿用 `bindHorizontalDragDelegate` 的 threshold，不另设 |
| 过冲上限 | **6px** | 回弹时的最大越界，超过就读成"弹跳玩具" |
| 超限阻力 | **0.35** | 到边界后：指针 10px → 物件 3.5px |
| 同刻并发 | **1** | 全屏同一时刻只允许一个拟物动作在跑 |
| 承接件 | **≤1** | 一个动作里最多出现一个"影子"或一个"描边" |

### 1.3 降级（不是可选项）

`prefers-reduced-motion: reduce` 下，四个动作**一律**退化为：
**直接到终值 + 200ms 淡入**（旧物件淡出 → 新物件淡入），不做位移、不做吸附、不做回弹。
这条沿用 `motion.js` 已有的 `prefersReducedMotion()` 口径，不许各写一份。

## 2. 四个动作

### A. 书签抽取（bookmark pull）

**隐喻**　会话列表是一叠夹在书里的书签。把一枚抽出来 = 拿起它，准备插到别处。

**触发**　在左栏会话行上按住 → 横向拖出 ≥ 4px（阈值同 `bindHorizontalDragDelegate`）。

**量**

| 阶段 | 行为 |
|---|---|
| 起手 | 行 `.is-dragging`：加 `--skeu-lift` 影子，`translateX` 跟手 1:1 |
| 上限 | 位移 ≤ **行宽的 60%**；超出后阻力 0.35（"快抽到底了"） |
| 抽出态 | 行右侧露出一个 **2px 的槽**（`--border-hairline`），暗示"这里原来插着一枚" |
| 落点高亮 | 悬停到中栏/右栏时，目标容器挂 `.is-drag-over`（**已有类**），只改背景 `--surface-2`，**不加描边、不加阴影** |
| 插回 | 松手回原处：`--skeu-settle` 归位，过冲 ≤6px |

**落点语义**

| 拖到 | 结果 |
|---|---|
| 中栏 | 该会话在新页签打开（书签插进书里） |
| 右栏 | 该会话分屏对照 |
| 原处 | 插回（回弹） |

**反方向**　中栏页签拖回左栏 = 书签收回。

**降级**　`reduced-motion` → 右键/长按弹出「打开到中栏 / 对照到右栏 / 取消」菜单，无拖动。

**判据**　拖动中 `translateX` 与指针 1:1（±1px）；释放后 240ms 内归位；拖出过程中
**左栏宽度不变、中栏不位移**（不能整屏跟着动）。

**为什么值得做**　它是唯一一个把"会话归属"这个抽象关系变成手势的动作。
也是四个里最重的，建议**最后做**。

---

### B. 书本翻页（page turn）

**隐喻**　中栏是一次对话"当前这一页"；页签切换 = 翻页。

**触发**　中栏页签点击、`Ctrl+Tab`、或左右边缘横向拨动（复用 `.scroll-edges-x` 手势）。

**量**

| 项 | 值 |
|---|---|
| 旧页 | `translateX(-32px)` + `opacity → 0` |
| 新页 | `translateX(+32px)` → `0` + `opacity 0 → 1` |
| 方向 | 由页签在 tab strip 里的左右关系决定（左→右 = 新页从左进），**不是**固定方向 |
| 时长 | `--skeu-settle`（240ms） |
| 并发 | 两个页同时动，但它们是同一动作——不受"同刻 1"限制 |

**不做**　3D 翻卷、透视、卷曲、纸张纹理。那是装饰。

**判据**　翻转过程中，**顶栏、左栏、右栏、composer 的 bounding rect 必须逐帧不变**。
这条是"桌面不可动"的可自动断言形式。

**降级**　直接替换内容 + 200ms 淡入。

**为什么值得做**　它把"我在同一个会话的哪一层"讲清楚了，而且实现最轻（纯 CSS + 一个方向判断）。

---

### C. 滑动（slide）—— 面板抽屉

**隐喻**　左右栏是抽屉：推回柜体 = 收起，拉出来 = 展开。

**触发**　`Ctrl+B` / 点 rail 上的 chevron / 拖分隔条（`.panel-divider`，**已有 `.is-dragging`**）。

**量**

| 触发方式 | 行为 |
|---|---|
| 拖分隔条 | 宽度跟手 1:1；`.is-dragging` 期间分隔条自己加高光（**已有** `0 0 10px 1px accent55`） |
| 松手 | 吸附到最近档：`0` / 记忆宽度 / 上限，用 `--skeu-enter`（160ms） |
| 点按钮 | 宽度 `200ms` 线性到 0（**不做整屏位移动画**） |

**关键**　抽屉收起时，**内容区随 flex 扩张，而不是整体位移**。
"整屏平移"会让壳也跟着动，违反"桌面不可动"。

**判据**　拖动中 `内容区宽 = 容器宽 − 抽屉宽`（±1px）；松手后 160ms 内到达档位；
收起过程中顶栏不位移。

**降级**　直接切宽度，无过渡（避免"慢慢挤压"造成的重排抖动）。

---

### D. 拉伸（stretch）—— 弹性带

**隐喻**　终端面板上沿、composer 底边是弹性带：能拉长，但有极限。

**触发**　拖 `.terminal-resize`（**已有 `.is-dragging`**）；composer 输入超过 1 行自动长高。

**量**

| 项 | 值 |
|---|---|
| 跟手 | 1:1（未到上限） |
| 上限 | 终端面板 ≤ **视口高 60%**；composer ≤ **30 行** |
| 超限 | 阻力 0.35（指针 10px → 面板 3.5px） |
| 回弹 | 释放后 200ms 回到限位，过冲 ≤4px |
| 长高 | composer 每加一行 = 行高整数倍，**不做数字滚动、不做缓动**（打字时不抖） |

**判据**　未超限时 1:1；超限时 10px → 3.5px（±0.5px）；composer 长高时底部按钮组**不下移重排**两帧以上。

**降级**　`reduced-motion` → 直接跳到终值。

## 3. 四个动作的统一约束（一张表）

| 约束 | 值 | 违反的症状 |
|---|---|---|
| 跟手比 | 1:1 | 拖起来"粘"或"打滑" |
| 起手阈值 | 4px | 轻点被误判成拖动、或拖动被吞 |
| 过冲上限 | ≤6px | 像弹簧玩具 |
| 超限阻力 | 0.35 | 拉不到底、或拉到底还在飞 |
| 同刻并发 | 1 | 一次手势触发两个动作 |
| 承接件 | ≤1 | 圆角 + 黑影一起回来（就回到用户说的"丑爆了"） |
| 新增阴影 | **0** | 必须复用 `--shadow` / `--shadow-sm` |
| 新增圆角档 | **0** | 必须复用 `--r-*` 阶梯 |
| 壳位移 | **0** | 顶栏/左右栏跟着动 |
| 降级 | 必须实现 | 违背系统偏好 |

### 禁止清单

扫光 / 呼吸 / 粒子 / 连点 / 3D 透视翻转 / 模糊背景 / 音效 / 震动 /
"拖到哪里都跟手"（无边界）/ 拖动时整屏缩放。

## 4. 落地：挂点在哪（文件级）

| 动作 | 现有挂点 | 需要新增 |
|---|---|---|
| **A 书签** | `.is-dragging` / `.is-drag-over` 类已存在（页签、团队成员条目）；`motion.js` 的阈值逻辑可复用 | 会话行的拖拽源（pointer 事件，非 HTML5 DnD——避免与页签换序抢手势，沿用 `bindHorizontalDragDelegate` 里那条 `[draggable=true]` 让路规则）；中栏/右栏的 drop 目标 |
| **B 翻页** | `.dock-host` / `.conversation-tab` / `.right-tab` | 一个方向判定 + 两个 keyframes（纯 CSS + 一行 JS） |
| **C 滑动** | `.panel-divider.is-dragging`、`.resize-pill`、`dock-layout.js` | 吸附档位记忆（localStorage，与 `seelex.skin` / `seelex.mode` 同族命名） |
| **D 拉伸** | `.terminal-resize.is-dragging`、composer 自增高 | 上限与阻力系数（两个常量） |

**共享件**：`motion.js` 里加三个纯函数（可 `node --test` 直测，符合该文件既有口径）：

```js
export function resist(overflow, factor = 0.35)              // 超限位移压缩
export function settleIndex(value, stops)                    // 最近档吸附
export function pageDirection(fromIndex, toIndex)            // 翻页方向：-1 | 0 | 1
```

## 6. 与视觉优化的关系（顺序不能反）

```
DESIGN-LANGUAGE.md   ← 定语言（含：渐变、圆角纪律、阴影纪律、线框纪律）
        ↓
OPTIMIZATION-PLAN.md ← 先把丑的拆掉（P0-2 拆"圆角 + 黑下框"、P0-3 重写阴影 token）
        ↓
MOTION-LANGUAGE.md   ← 再谈动（复用拆完之后的 --shadow / --r-*，一个新件都不加）
```

**反过来的代价**：如果先做动效，拖动时用的还是 `rgba(0,0,0,.30)` 与 `border-radius: 999px`，
那"丑爆了"会被动画**放大**（黑边在运动中最显眼）。所以顺序是硬的。

## 7. 拍板结果（两点，2026-09-24 定案：都按推荐）

1. **书签抽取的手势**：用"按住横向拖出"（与页签换序的手势邻近，需要让路规则），
   还是更保守的"右键菜单 → 打开到中栏/对照到右栏"（无拖动学习成本）？
   ✅ **已定案：先做菜单版**（M2a），观察真实使用频次，再决定是否升级成拖拽（M2b）。
2. **抽屉收起时内容区行为**：随 flex 扩张（推荐，壳不动），还是内容区一起平移
   （视觉上"整屏在动"，与"桌面不可动"冲突）？
   ✅ **已定案：随 flex 扩张**（当前 CSS 行为即如此，无需改动）。
