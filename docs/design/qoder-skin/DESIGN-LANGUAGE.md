## 1. 中心命题：一层环境渐变（ambient gradient）

### 1.1 它是什么

Qoder 的"通透"不来自模糊、不来自毛玻璃、不来自半透明。它来自**一整块壳共享一条竖向渐变**，
而内容区是盖在壳上的一张纯白纸。

```
┌──────────────────────────────────────────────┐
│  顶栏：整宽，平色 = 渐变的【起点色】            │  ← 高度 56px
├────────────┬─────────────────────────────────┤
│            │                                 │
│  左栏      │   内容纸：纯白 #FFFFFF            │
│  渐变      │   （盖在壳上，不是壳的一部分）    │
│  全程扫过  │                                 │
│  316px     │                                 │
│            │                                 │
└────────────┴─────────────────────────────────┘
   ↑ 壳 = 渐变；纸 = 纯白；两者之间 1px #E6E6E6
```

**这解释了用户那句「渐变从左侧框去到顶栏」**：顶栏显示的其实是渐变的起点色，
它和左栏顶端**同一个颜色**，中间没有线也没有色差，于是眼睛把它们读成"一片连续的场"——
渐变看起来是从左框"流"到顶栏的。它不是真的有横向渐变，而是**同色相接**造成的连续感。

### 1.2 实测量

沿左栏一条干净竖线（x=270，避开会话标题与图标）取 21 个控制点：

| y | 颜色 | H | S | L |
|---|---|---|---|---|
| 4 | `#EBEBC6` | 60° | 48.0% | 84.9% |
| 204 | `#E7E8CB` | 63° | 38.7% | 85.3% |
| 404 | `#E1E5D0` | 70° | 27.9% | 85.7% |
| 604 | `#DDE2D6` | 84° | 16.6% | 86.2% |
| 754 | `#D9E0DA` | 127° | 9.3% | 86.4% |
| 904 | `#D6DDDD` | 181° | 10.2% | 85.2% |
| 1004 | `#D3DCE0` | 202° | 18.1% | 85.4% |

### 1.3 配方（可直接抄）

```css
linear-gradient(180deg, #EBEBC6 0%, #D1DAE2 100%)
```

三条性质都是实测出来的，不是猜的：

1. **纯竖直**：同一 y 上取 x=8 / 120 / 240 三点，最大通道差 **0.0**；
2. **线性 sRGB**：R/G/B 三通道线性拟合 **R² = 0.999 / 0.998 / 0.999**，
   中点实测 `#DEE3D4` = 两端线性插值（差 ≤1/255）；
3. **亮度恒定**：L 从 84.9% 走到 85.3%，**全程波动 < 2%**。

第 3 条是全部秘密所在。它**不是明暗渐变**（那会读成"打了阴影/被照亮"），
而是**等亮度的色温扫过**：色相 60°(黄) → 207°(青蓝)，饱和度 48.9% → 22.9%，
中途 y≈754 处甚至掉到 9%（线性插值穿过中性轴的几何结果）。

> 所以它读起来像"一块被光穿过的玻璃"，而不是"涂了颜色的板子"。这就是「通透」。

### 1.4 结构参数

| 项 | 实测 | 说明 |
|---|---|---|
| 顶栏高 | 56px | y=55 一行 `#E6E6E6`，y=56 起纯白 |
| 左栏宽 | 316px | x=315 一行 `#E6E6E6`，x=316 起纯白 |
| 壳 ↔ 纸 发丝线 | 1px `#E6E6E6` | **中性灰**，不是暖色 |
| 内容纸 | `#FFFFFF` | 纯白，无渐变 |

### 1.5 落地：它必须是 token，不能写死

渐变是**颜色**。按 `gui/frontend/dist/themes/README.md` 的契约，颜色属于皮肤包——
所以它不能硬编码进 `styles.css` 的选择器，得进契约 token 清单：

```css
/* styles.css :root —— 新增契约 token */
--shell-gradient: linear-gradient(180deg, #EBEBC6 0%, #D1DAE2 100%);
```

用法（**壳**承载渐变，**纸**盖上去）：

```css
.app-shell        { background-image: var(--shell-gradient); }
.topbar,
.left-panel,
.right-panel      { background: transparent; }   /* 让壳的渐变透出来 */
.workspace        { background: var(--surface); } /* 白纸 */
```

> 注意：`themes/README.md` 的契约 token 清单必须同步加 `--shell-gradient`
> （以及深色皮肤要给自己的那一份）。**不改 JS**。

> **落地更新（2026-09-24，两轴换代）**：渐变是颜色，属**皮肤轴**。按用户「皮肤和深浅色分开来做」
> 的口径，最终落法是皮肤给两条变体 token `--skin-gradient-light` / `--skin-gradient-dark`，
> `styles.css` 在深浅两套基座里各桥接一次：
> ```css
> :root                      { --shell-gradient: var(--skin-gradient-light, linear-gradient(180deg, #EBEBC6, #D1DAE2)); }
> :root[data-theme="dark"]   { --shell-gradient: var(--skin-gradient-dark,  linear-gradient(180deg, #1B1A17, #171A1E)); }
> ```
> 于是"每套皮肤一副渐变色、且深浅各取一份"，5 皮肤 × 2 深浅都不串味。

### 1.6 深色版（Hypothesis，待实机验证）

手头**没有** Qoder 深色实机截图，所以下面这条按"同样的三条性质"推导，标记为待验证：
**等亮度 + 纯竖直 + 线性**，把主轴从"黄→青蓝"换成"暖灰→冷灰"，L 压到 ~11%：

```css
/* 皮肤 qoder 的深色变体（已落地到 themes/qoder.css）： */
--skin-gradient-dark: linear-gradient(180deg, #1B1A17 0%, #171A1E 100%);
```

验证方法：拿到深色截图后跑
`python docs/design/qoder-skin/tools/measure-skin.py gradient <png>`，
看 L 是否仍在一条水平线上、横向差是否仍为 0。

### 1.7 判据（可验收）

- 左栏顶端取色 = `#EBEBC6` ±2，底端（y=1079）= `#D1DAE2` ±2；
- 任一 y 上横向三点最大通道差 ≤2；
- 顶栏取色与左栏顶端色差 ≤2（"同色相接"成立）；
- 数值拟合 R² ≥ 0.99，且亮度全程波动 <2%；
- 内容区（x>320, y>60）取色 = `#FFFFFF`。

复现：
```bash
python docs/design/qoder-skin/tools/measure-skin.py gradient \
       docs/design/qoder-skin/refs/qoder-light-clean.png 270 4 1054
```

## 2. 层级：三段面，靠色温分层，不靠描边

| 层 | 材质 | 允许的手段 | 禁止的手段 |
|---|---|---|---|
| 壳 | 渐变玻璃板 | 一条渐变 | 描边、投影、模糊 |
| 纸（内容） | 纯白纸，零厚度 | 与壳之间 1px 中性发丝线 | 投影、内阴影、"内嵌"效果 |
| 浮层（菜单/弹窗/toast） | 白卡片，浮起 | 1px 描边 + 极轻投影 | 渐变填充、发光、深色阴影 |

**判据**：把截图去色，三层仍能靠亮度分开；同时整屏"硬线"数量 ≤ 3 类
（面板边界 / 输入面描边 / 数据表格线）。

## 3. 几何：一档圆角阶梯 + 一条铁律

### 3.1 实测阶梯

| 元素 | 半径 | 证据 |
|---|---|---|
| 输入区 composer | **14px**（1197×149） | `radius` 子命令：顶行墨段起于 x=355、满宽行起于 x=341 → 14；角剖面 dy 0→14 … 14→0 |
| 发送键 | **6–8px**（35×35 **圆角方，不是圆**） | 角剖面 dy 0→6 … 6→0（松阈值）/ dy 0→8 … 8→0（严阈值）；圆的话半径会是 17.5 |
| 数据胶囊 / chip | 全胶囊（999px） | 目视 + 高宽比 |
| 列表行 | **无底、无框、无圆角** | 左栏 y=872..920 逐像素：整段只有文字，没有胶囊填充 |
| 分节标签 | 无 | 纯文字 |
| **内容纸（对话区整块）** | **7–8px，且四边不缩进** | `refs/qoder-light-clean.png` 逐像素：顶左 (323,56)→(316,63)、顶右 1907→1913、底 y=1070 行左 319 / 右 1910 |

**内容纸的圆角是"圆弧里露出壳"，不是"缩进留白槽"**：纸的左 / 右 / 下三边与窗口齐平
（x=316 / x=1913 / y≈1076 都是纸），只在四个角的圆弧里透出侧栏与窗底。所以落地只需要
"给那张纸一个 8px 圆角 + 让壳在它背后透出来"——**不需要 margin、不需要额外描边**。
（2026-09-24 落地：`styles.css` 第 27 节 n，半径取 `--r-md`；本产品的中栏就是那张纸。）

> ⚠️ 这条与当前 `styles.css` 第 27 节 m) 冲突：那里把发送键改成了 `border-radius: 999px`
> （圆键）。**实机量出来是 8px 的圆角方**。见 `OPTIMIZATION-PLAN.md` P0-2。

### 3.2 铁律：**圆角 ≠ 允许在它下方压一条深色边/影**

这是用户"圆角配上一个黑色的下外框真的丑爆了"的可判定形式：

> 一个带圆角的元素，其下边界只能出现两种东西：
> **(a)** 与它同色温的分层底色，或 **(b)** 1px 中性发丝线。
> **不允许出现**：深色投影、深色描边、深色三角/缺口、深色内阴影。

当前 `styles.css` 里正好踩满这条（原文摘录）：

```css
.right-tab { border-radius: var(--r-md) var(--r-md) 0 0; border-bottom: 0; }
.right-tab.is-active {
  background-image: linear-gradient(180deg, var(--accent-strong), var(--accent));
  border-color: color-mix(in srgb, var(--accent) 65%, var(--border-strong));
  box-shadow: 0 3px 8px rgba(0, 0, 0, .30),  /* ← 黑色下外框 */
              inset 0 1px 0 color-mix(in srgb, #ffffff 34%, transparent);
}
.right-tab.is-active::after {                 /* ← 深色三角缺口，还带黑影 */
  bottom: -5px; height: 6px; clip-path: polygon(0 0, 100% 0, 50% 100%);
  background-color: var(--accent); box-shadow: 0 2px 4px rgba(0, 0, 0, .25);
}
```

第 27 节 j) 只覆盖了 `box-shadow`，`::after` / `::before` / `border-color` 三处**是残留**，
所以这个"丑爆了"的组合至今还在页面上。

### 3.3 「过圆角」的可判定定义

不靠感觉，靠四条：

1. 半径 > 元素高度的一半 → **过圆**（刻意的胶囊与圆点豁免）；
2. **同一层级内出现 ≥2 档半径**（不是"父 14 子 8"，是"两个兄弟用了 14 和 8"）→ 过圆；
3. **一屏内"大圆角"（≥14px）超过 1 处** → 过圆（Qoder 全屏只有 composer 一处）；
4. 卡片半径 ≥ 子元素半径之和的一半（如卡片 16px 里再放一个 16px 的块）→ 过圆。

当前 `styles.css` 的风险点：`border-radius: 999px` 出现 **33 次**、
`var(--r-md) var(--r-md) 0 0` 出现 **4 次**、非 token 硬编码半径
`8px×4 / 5px×2 / 6px / 4px / 3px / 2px / 1px` 共 10 处。审计清单见优化方案 P1。

## 4. 阴影：全屏只允许三处

| 允许 | 理由 |
|---|---|
| 浮层（菜单 / 弹窗 / toast / tooltip） | 它真的浮在纸上面 |
| 拖拽中的分隔条 | 只在拖动期间 |
| ~~composer~~ | **实机是"0 影 + 1px `#DDDDDD` 描边"**；当前 Seelex 给了 `--shadow-sm`，这是不合时宜的阴影 |

阴影的**质量**同样有判据——"深而不黑"：

- 颜色：中性或与底色同色温，**禁止 `rgba(0,0,0,α)`**（黑影在暖色壳上会发脏）；
- 透明度：**≤ 10%**；
- 模糊半径：**≥ 16px**（小于 16px 读成"描边"而不是"高度"）；
- y 偏移：**≤ 4px**（大于 4px 读成"在下边贴了条黑边"）。

当前全文件 **70 处 `box-shadow`**：`--shadow` 7 处、`--shadow-sm` 8 处，
另有 `inset` 系 20+ 处、`rgba(0,0,0,.30)` / `rgba(0,0,0,.25)` 各 1 处（就是第 3.2 节那两条）。

## 5. 线框：删到只剩"结构线 + 数据线"

用户的口径是「**减少不必要的线框，但保留文件树里必要的线框**」。

### 5.1 删（装饰线）

- 列表行之间的分隔线（会话、工具、历史——**行与行之间不需要线**，靠间距）；
- 页签行底下的**通栏横线**（`.conversation-tabs` / `.right-tabs` 的 `border-bottom`）；
- 卡片与卡片之间的框（靠底色分层或间距）；
- 分区标签上下的通栏线。

### 5.2 留（结构线 / 数据线）

| 保留 | 为什么 |
|---|---|
| **文件树**的缩进导引线 / 树轨（`--tree-rail`） | 用户点名。树轨是"层级"的唯一视觉载体，删了树就散了 |
| 表格网格（`work-row` / excel 单元格行列线） | 数据对齐靠它；这是"数据线"，不是装饰 |
| 输入面描边（composer 1px） | "可输入的边界"是语义，不是装饰 |
| 面板之间 1px 发丝线 | Qoder 实机也有（`#E6E6E6`），它是"壳/纸"的接缝 |
| 代码块外框 | 代码是"外来物"，需要边界 |

### 5.3 颜色与剂量

- 接缝线统一 **中性**：`#E6E6E6`（面板）/ `#DDDDDD`（输入面）；
- 同一屏同类线**只能一档**（不能深浅两套并存）。

当前 `styles.css`：`border-bottom` 39 处（含 `1px solid var(--border)` 24 处）、
`border-top` 28 处（含 19 处）、`border` 193 处（`1px solid var(--border)` 85 处）。
不是都要删——但要按 5.1/5.2 分类逐条判。
