## 结论先行

1. **用户面退场已证实**：2026-10-12 J-1a 删除旧 Agent Team 面板、`@<团队>` 召唤、旧 `team.*` headless RPC、团队库/员工库/全局母本的用户装配入口；现行产品团队面是 `team_*` 的 leader-worker teamwork，不是旧的发言环。
2. **`$plan` 口径存在反向漂移**：旧 `$plan` Skill/`$plan-efficiency` 已移除；但 `plan_load`/`plan_run` 等 DAG 工具仍在 Bridge 生产注册，并由 goal Skill 激活策略控制可见性。`plugins/default/plugin.md` 与 `plugins/default/README.md` 把“无 `$plan` Skill”写成“工具面没有 plan 工具”，与当前代码冲突。应修文案，不应删除 WorkPlan 底层能力。
3. **席位轮转退场不等于角色系统退场**：`KindSeat`、治理 seat loop、员工库 CRUD 不再是用户能力；逻辑 `role_name`、角色会话锚、worker 执行主体/权限、ADVISOR 内部执行、message 角色归属、teamwork 计划成员与 subagent 仍有实际运行或兼容用途。

5. **持久字段和恢复不可随 UI 一起删**：`order_policy/order_roles`、`role_name/role_session_id`、旧 `retire` 审计 kind、历史 role registry/role draft/message/floor 以及 teamwork/subagent 中断恢复属于格式兼容或执行事实。是否还有活跃生产读写需按字段分别证明；不得因为入口消失就删字段、旧文件或恢复代码。
6. **本次确认的待删重复实现：0**。`workunit.ProgressOf` / `EncodeStages` / `DecodeStages` / `ClipPreview` 已记录为已有收敛点；本轮没有找到需再次合并的同判据同语义双实现。`agentteam.RoleSessionID` 与 `teamwork.DefaultRoleSessionID` 看似相似，但空 team ID、空白裁剪和默认身份语义不同，暂不构成可安全合并证据。

## 分类口径

- **过时文案**：只更新状态、替代能力链接和实现时间，不删除历史经过。
- **仍有效底层能力**：保留生产执行、权限、身份、持久化或恢复路径；用户入口是否开放另行处理。
- **不可达实现**：要求从生产装配、调用点、注册、反射/字符串 RPC、持久化恢复路径同时查不到；测试引用不能伪装为生产调用。无来路但仍有兼容签名/格式依赖时，列为候选而非立即删除。
- **兼容/迁移代码**：保持旧格式读取、标识稳定、失败显式；须有数据迁移及退出条件后才能删。
- **历史记录**：标为历史并链接现状，不因文案陈旧而删档。
- **重复实现**：仅在判据、语义相同且漂移会造成损害时成立；必须列“原位置 → 唯一实现位置”。相似的命名/代码形状不够。
